## 1. ExactBeamEnergy — máxima energía sobre todos los campos

**Problema:** Planes con campos mixtos (6X + 10X) aparecían como "3DC - 6X".  
**Fix:** `AriaQuery.DetermineExactBeamEnergy` y `AriaAdapter.ResolveExactBeamEnergy` ahora iteran TODOS los campos del plan y usan la energía máxima.  
**Regla:** Si al menos un campo tiene 10X/15X/18X, el plan se etiqueta con esa energía.

## 2. run-query: fire-and-forget con polling

**Problema:** El botón "Actualizar ARIA" bloqueaba el browser 15 min.  
**Fix:**
- `POST /api/aria/run-query` ahora devuelve **202 Accepted** inmediatamente; AriaRunner corre en `Task.Run` en background.
- `GET /api/aria/query-status` devuelve `{ isRunning, progressPct, currentPatient, totalPatients, lastRunSucceeded, ... }`.  
  Lee el log del AriaRunner para calcular progreso (regex `[X/Y]` en los últimos 4KB).  
  Usa `File.GetCreationTimeUtc` para encontrar el log correcto.
- Frontend (`app.js`): `actionUpdateAria` maneja 202/409, hace polling cada 4 segundos mostrando `"Consultando ARIA... 45% (476/619)"`, luego llama `apply-aria` automáticamente.
- `AriaJobState.cs`: singleton en `Meva.Rt.Web` con `TryStart()` / `Complete()` / `ReadProgress()`.

## 4. BQT/IORT ignorados cuando hay otro tratamiento en SitraMed

**Problema:** Pacientes con tratamiento combinado (BQT + IMRT) mostraban BQT.  
**Fix en dos paths:**
- **Playwright** (`PlaywrightSitraMedClient.cs`): JS itera todas las celdas de la fila, guarda BQT/IORT como fallback, retorna el primer tratamiento principal.
- **HTML/Regex** (`SitraMedExtractors.cs`): `ResolveTreatmentZone` usa `Matches()` en vez de `Match()`, descarta BQT/IORT si hay otra técnica presente.

**Nota:** El fix entra en efecto en el próximo scraping de seguimiento (refresh completo).

## 5. Tab "Derivación" — herramienta organizativa

Herramienta de solo lectura (no modifica SitraMed ni ARIA). Decisiones se registran en HTML exportado.

### Flujo
1. **Configuración:** Seleccionar equipo fallido + rango de fechas + checkbox "incluir planificación".
2. **Calcular:** Fetch de agenda en paralelo (`Promise.all`) para todos los días hábiles del rango.
3. **Lista pacientes (columna izquierda, 50%):**
   - **Fuente A:** Turnos reales (`IsEstimated = false`) en el equipo seleccionado, agrupados por GUID.
   - **Fuente B (si checkbox):** Pacientes de followup con `PlannedMachineDisplayName == equipo` y etapa con `SortOrder >= F6A`.
   - Cada tarjeta: nombre + HC, badge técnica, horario actual (🕐 dd/mm HH:mm), fechas/etapa.
   - **3 botones rápidos** con los equipos más compatibles (mismo centro primero).
   - **Dropdown "Otros..."** con equipos restantes.
   - Badge de estado + botón ⊗ suspender.

4. **Panel derecho (50%):** Tarjetas de equipos destino.
   - Ordenadas: con derivados primero → mismo centro (★) → resto.
   - Cada tarjeta: nombre, centro, **turnos disponibles** (verde/amarillo/rojo), lista de pacientes derivados con botón ✕.

5. **Barra inferior fija:** Total / Derivados / Suspendidos / Sin asignar. Botones Exportar HTML / Exportar igual.

### Compatibilidad por TreatmentLabel
| Label | Requiere |
|-------|---------|
| VMAT, SBRT-VMAT, RC-VMAT | `canDoVMAT` |
| IGRT-VMAT | `canDoVMAT` + ⚠ |
| SBRT, SBRT-haz SRS | `canDoSBRT` |
| RC, RC-haz SRS | `canDoRC` |
| TBI | `canDoTBI` |
| TSET, 3DC e- | `canDoElectrons` |
| 3DC 10X/15X/18X | `highEnergyBeams.includes(...)` |
| IGRT, IGRT-estático | siempre compatible + ⚠ |
| IMRT-estático, 3DC, 3DC-6X | siempre compatible |
| BQT, IORT | incompatible |

### Export HTML
Genera HTML autocontenido con tabla de derivaciones (derivados → suspendidos → sin asignar) + resumen por equipo. Descarga como `derivacion_[equipo]_[fecha].html`.

### Cálculo de slots/turnos
`turnosLibres = floor((workingHours - reservedSpecialHours) × 60 / standardSlotMinutes) × diasHábiles - turnosOcupados(agenda real) - derivadosAsignados`
