- `date: null` → "EQUIPO: sin disponibilidad en agenda actual"

Matching robusto: exact → case-insensitive → fallback via `homeData.equipments[]`.

## 2. Fix BQT/IORT en Agenda de Equipos

**Problema:** Pacientes con `treatmentLabel = "BQT"` o `"IORT"` aparecían en la agenda de equipos (LINACs). Ej: HC 1-117066-1 en Meva Central - Equipo 1.

**Causa raíz:** En `BootstrapService.BuildAsync()`:
- Path A (paciente en followup): el label viene del followup `TreatmentTechnique`. El fix de `c8cc3e5` (`ResolveTreatmentZone`) prefiere no-BQT, pero si el paciente solo tiene BQT en SitraMed, devuelve BQT correctamente.
- Path B (agenda-pura): `TreatmentClassifier.Classify(item.Treatment)` sobre texto crudo, sin filtro.

En ambos casos el slot llega al frontend con `treatmentLabel = "BQT"`.

**Fix (app.js):** Nueva función `isExcludedSlot(slot)`:
```javascript
function isExcludedSlot(slot) {
  const t = (slot.treatmentLabel || '').split(/[\s-]/)[0];
  return t === 'BQT' || t === 'IORT';
}
```

Aplicada en tres lugares:
1. `renderAgendaMachineCards()` — excluye del conteo de slots y cálculo de capacidad libre
2. `renderAgendaDetail()` — excluye del panel de detalle (no se muestran al usuario)
3. `_pacienteFirstAvailableSlot()` — excluye del conteo de ocupación al buscar disponibilidad

## 3. Auto-refresh (polling de estado)

**Problema:** Usuarios con la web abierta no ven datos nuevos tras un scraping, ni código nuevo tras un deploy.

### Backend: `GET /api/status`
```
{ generatedAtUtc: "2026-06-16T10:30:00Z", appVersion: "1750078234" }
```
- `generatedAtUtc`: del snapshot `dashboard_bootstrap.json`
- `appVersion`: Unix timestamp de `File.GetLastWriteTimeUtc("wwwroot/app.js")` → cambia en cada `dotnet publish`

### Frontend: polling cada 3 minutos

```
Boot → setTimeout(_checkStatus, 10s)  → registra baseline (sin recargar)
     → setInterval(_checkStatus, 3min) → compara
```

| Condición | Acción |
|-----------|--------|
| `appVersion` cambió | Banner azul "Nueva versión disponible. Actualizando..." → `location.reload(true)` en 2.5s |
| `generatedAtUtc` cambió | Banner azul "Datos actualizados. Recargando..." → `location.reload()` en 1.5s |
| Sin cambios | Nada |

El `index.html` tiene `Cache-Control: no-store`, así que `location.reload()` siempre trae datos frescos del servidor.
