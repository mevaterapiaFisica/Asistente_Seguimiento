## 2. Paralelización SitraMed (`PlaywrightSitraMedClient.cs`)

### Problema
El scraping de SitraMed era secuencial: cada combinación de centro×etapa abría una página Playwright y esperaba su descarga antes de la siguiente.

### Solución
- Login único via `CreateLoggedPageAsync` → `IBrowserContext` compartido
- `SemaphoreSlim(MaxParallelPages = 4)` controla concurrencia máxima
- `session.Context.NewPageAsync()` crea múltiples `IPage` que comparten las cookies de sesión
- `Task.WhenAll(tasks)` ejecuta todas las combinaciones en paralelo
- Patrón aplicado en tres métodos: `DownloadFollowUpPagesAsync`, `DownloadAgendaPagesAsync`, `DownloadAgendaPagesForDatesAsync`

### Paralelización agenda+seguimiento (`Contracts.cs`)
```csharp
var agendaTask = _agendaExtractor.ExtractAsync(cancellationToken);
var followUpTask = _followUpExtractor.ExtractAsync(cancellationToken);
await Task.WhenAll(agendaTask, followUpTask);
```

## 3. Bulk Query ARIA (`AriaQuery.cs`, `Program.cs`)

### Problema
938 pacientes consultados individualmente (1 query SQL por paciente) → ~17 min.

### Solución: 6 consultas WHERE IN

| Query | Contenido |
|-------|-----------|
| 1/5 | Patients + PatientDoctors WHERE PatientId IN (...) |
| 2/5 | Courses WHERE PatientSer IN (...) |
| 3/5 | PlanSetups + Prescription + RTPlans WHERE CourseSer IN (...) AND Status != 'Rejected' |
| 4/5 | Radiations + RadiationDevice + EnergyMode + Technique WHERE PlanSetupSer IN (...) |
| 5/5 | ExternalFieldCommons GROUP BY RadiationSer COUNT(ControlPoints) — evita JOIN cartesiano |
| 6/6 | Ensamblado en memoria con Lookups |

Helper `QueryInBatches` fragmenta listas > 500 keys (límite SQL Server de 2100 parámetros).

`Program.cs`: eliminado `Parallel.ForEach` + `ConcurrentBag` + `--workers`; reemplazado por `query.QueryAllPatients(input.PatientIds)`.

## 4. Fix: duplicados en ToDictionary (`Contracts.cs`)

**Error:** `System.ArgumentException: An item with the same key has already been added. Key: 1-98512-1`

Ocurría al construir el diccionario de preservación de `TomographyDate`/`ResponsibleDoctor` cuando un paciente aparecía dos veces en el snapshot previo.

**Fix:** `.GroupBy(...).ToDictionary(g => g.Key, g => g.First()...)` en lugar de `.ToDictionary(p => p.PatientId, ...)`.

## 5. Fix: despliegue AriaRunner net9.0-windows

El build publicado en `publishnet48/` era correcto para net48 pero el despliegue en `C:\MevaRT\AriaRunner\` usaba el formato net9.0-windows (exe apphost + dll managed assembly). Se publicó correctamente con `-f net9.0-windows` y se desplegaron `AriaRunner.exe` + `AriaRunner.dll`.
