# Sesión 2026-06-18

## Cambios implementados

### 1. Derivación: detección automática de pacientes atendidos

Al presionar "Calcular derivación", el sistema ahora scrapea la agenda del equipo fuera de servicio para detectar qué pacientes ya fueron atendidos en la fecha de interés.

**Backend:**
- Nueva interfaz `IAttendedPatientsExtractor` en `Meva.Rt.Application/Contracts.cs`
- Clase `SitraMedAttendedPatientsExtractor` en `SitraMedExtractors.cs`: scrapea la agenda del equipo y detecta botones "Atendido" para extraer los GUIDs correspondientes
- Nuevo método `DownloadAgendaPageHtmlForMachineAsync` en `PlaywrightSitraMedClient.cs`
- Endpoint `GET /api/derivation/attended-patients?machine=...&date=...` en `Program.cs`

**Frontend (`app.js`, `index.html`, `styles.css`):**
- `_calcularDerivacion`: busca agenda + atendidos en paralelo; auto-marca pacientes atendidos con `{ estado: 'atendido', equipo: null }`
- `_fetchAttendedGuids`: un fetch por fecha via `Promise.allSettled`; muestra banner de advertencia si alguna fecha falla
- `_buildDerivCard`: pacientes atendidos no muestran botones de acción ni selector de equipo
- `exportarDerivacion`: sección separada "Pacientes ya atendidos al momento del cálculo" antes de la tabla de derivaciones
- Banner `#derivAttendedWarning` (ámbar) cuando no se puede verificar

### 2. Fix: técnica de tratamiento extraída de SitraMed (causa raíz)

**Síntoma:** Paciente NÚÑEZ, Justo Justino (1-118785-0) aparecía como "RC-VMAT" en vez de "IMRT/VMAT", y en stage F7C "Chequeo General" en vez de F9 "Placa Verificadora".

**Causa raíz (técnica):**
El extractor de Playwright itera celdas `<td>` del `<tr>` del paciente. La celda "Comunicaciones Internas" (índice 5) contiene todo el HTML del modal con las notas administrativas, incluyendo una nota del 29/04/2026 que mencionaba "RxCx" (derivación anterior). Como `TreatmentClassifier` chequea "RxCx" antes que "IMRT", retornaba RC. La celda con el link `conduct_definitions` ("Intensidad Modulada - meningioma") nunca se alcanzaba porque el loop retornaba antes.

**Causa raíz (stage):**
El paciente pasó a F9 el mismo día de la sesión; el snapshot anterior (3:34 PM) lo capturó mientras todavía estaba en F7C. Un nuevo scrape confirmó F9 inmediatamente.

**Fixes aplicados:**

`PlaywrightSitraMedClient.cs` — extracción JS del treatmentZone:
```javascript
// 1. Primero chequear el link conduct_definitions (fuente autoritativa)
const conductLink = tr.querySelector('td a[href*="conduct_definitions"]');
if (conductLink) {
    const text = (conductLink.textContent || '').trim();
    if (text.length > 2) return text;
}
// 2. En el fallback por keywords, saltar celdas con modal
if (cells[i].querySelector('.modal, button.modal-button')) continue;
```

`TreatmentClassifier.cs`:
```csharp
if (t.Contains("IMRT", StringComparison.OrdinalIgnoreCase)
    || t.Contains("Intensidad Modulada", StringComparison.OrdinalIgnoreCase)) return "IMRT";
```

`SitraMedExtractors.cs` — `ResolveTreatmentZone` (path local/ejemplos):
- Ahora ordena candidatos no-BQT/IORT por fecha descendente usando `ExtractRowDate`

**Resultado:** El paciente ahora muestra F9 "Placa Verificadora" + técnica IMRT + label "VMAT" (IMRT con entrega VMAT según ARIA).

## Diagnóstico y deployment

- Producción corre desde `C:\MevaRT\Meva.Rt.Web.exe` (servicio Windows `MevaRT`)
- Deploy: `dotnet publish Meva.Rt.Web/Meva.Rt.Web.csproj -c Release -o C:\MevaRT --nologo`
- Para diagnostics: agregar `MEVA_SITRAMED_DIAGNOSTICS=true` en `HKLM:\SYSTEM\CurrentControlSet\Services\MevaRT\Environment` y reiniciar. Archivos en `C:\MevaRT\data\diagnostics\followup\`
- Para forzar rescrape desde consola: `Invoke-RestMethod -Uri "http://localhost:5062/api/home/refresh" -Method POST`
