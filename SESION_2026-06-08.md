# Sesion 2026-06-08: Columna de Recomendacion de Equipo (tab Fisica)

## Cambios implementados

### 1. Estimacion de fecha de inicio — fuente dinamica de tiempos

**Problema:** La estimacion mostraba fechas en 2027 porque `weekly_stats.json` contenia una importacion historica masiva de todos los pacientes comprimida en 2 semanas, con promedios inflados (F9: 40 dias, F11: 67 dias).

**Solucion:**
- Se implemento `resolvePlanningTimeSource(weeklyStats)` que evalua la cantidad de semanas distintas con datos para las etapas criticas (`F6B`, `F6C`, `F6F`, `F6G`, `F7A`).
- Requiere **4 semanas** de datos reales antes de usar estadisticas; hasta entonces usa `expectedDays` (valores de referencia de configuracion).
- Se renombraron los archivos historicos a `.backup.json` y se crearon nuevos archivos vacios en `C:\MevaRT\data\`.

**Leyenda dinamica (3 estados):**
- Con estadisticas: `"Tiempos basados en estadisticas de las ultimas N semanas"`
- Con datos parciales: `"Tiempos basados en valores de referencia (N semanas acumuladas de 4 necesarias para usar estadisticas)"`
- Sin datos: `"Tiempos basados en valores de referencia (sin estadisticas acumuladas aun)"`

### 2. Tarjetas de tecnica — filtrado por paciente seleccionado

**Cambio:** Las tarjetas de tecnica ahora:
- **Con paciente seleccionado:** solo muestra las tecnicas relevantes para ese paciente (`TECH_HIGHLIGHT_MAP`)
- **Sin paciente:** muestra todas las tecnicas habilitadas en el centro
- Las tecnicas no correspondientes **desaparecen completamente** (no quedan como "no disponible")

**Mapeo de tecnicas:**
- `3DC` → 3DC-6X, 3DC-AltaE, 3DC-e
- `IMRT` → IMRT-estatico, IMRT-VMAT
- `IGRT` → IGRT (1 tarjeta)
- `RC` / `SBRT` → sus respectivas tarjetas

Se elimino la nota de ambiguedad "La modalidad exacta... se confirmara con ARIA".

**Layout:** Se cambio la grilla de 2 columnas a **1 columna** para mayor claridad.

### 3. Ranking de equipos — disponibilidad real

**Problema:** Todos los equipos mostraban 48 turnos libres y Equipo 3/4 siempre quedaban primeros porque el calculo usaba capacidad teorica maxima (horas trabajadas / slot).

**Solucion:** Se reemplazo `_fisicaDailySlots()` por `_fisicaFreeSlots()` que usa `agendaPatients` del bootstrap data (`state.homeData.equipments`):
```
turnos_libres = capacidad_total - agendaPatients
```

- Soporta **valores negativos** (cuando hay mas pacientes estimados que capacidad), mostrados en **rojo**.
- El ranking ordena de mayor a menor disponibilidad, con negativos al final.
- Se eliminaron los `Math.max(0, ...)` para permitir sobrecapacidad visible.

### 4. Cache del navegador — solucion definitiva

**Problema:** El navegador cacheaba `index.html` y no veía los `?v=...` actualizados en los scripts/CSS.

**Solucion:**
- Meta tag `Cache-Control: no-store, no-cache, must-revalidate` en `index.html`
- `UseStaticFiles` en `Program.cs` con `OnPrepareResponse` que agrega el mismo header para `index.html` desde el servidor
