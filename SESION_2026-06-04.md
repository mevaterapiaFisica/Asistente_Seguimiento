## Qué se implementó

### 1. Clasificación de técnicas (Core)
- `TreatmentClassifier.Classify()`: reglas en orden TSET→TBI→SBRT→RC→VMAT→IMRT→BQT→IORT→3DC (default)
- `TreatmentClassifier.BuildLabel(tech, modality, energy, beamFallback)`: combina datos de SitraMed + ARIA en un solo string legible. Ejemplos de output: `"VMAT"`, `"IMRT - estático"`, `"SBRT - VMAT"`, `"3DC - 6X"`, `"3DC 10X"`, `"TBI"`, `"TSET"`

### 2. Nuevos campos en el modelo (Core/DomainModels)
- `ProcessPatientSnapshot`: `IrradiationModality`, `ExactBeamEnergy`, `TreatmentLabel`
- `MachineAppointmentSnapshot`: `IrradiationModality`, `TreatmentLabel`
- `AriaPlanSnapshot`: `IrradiationModality`, `ExactBeamEnergy`
- `RtMachineCapabilities`: nueva clase con flags CanDoVMAT/SBRT/RC/TBI/TSET/IGRT/Electrones + HighEnergyBeams
- `RtSystemConfiguration`: agrega `MachineCapabilities`

### 3. AriaRunner — extracción de datos ARIA
- `AriaQuery.Modalidad()`: lee `TechniqueId` del primer haz → `"ARC"→"VMAT"`, `"STATIC"+>40CP→"IMRT"`, `"STATIC"+≤40CP→"3DC"`
- `AriaQuery.DetermineExactBeamEnergy()`: energía en keV → `"6X"/"10X"/"15X"/"18X"/"Electrones"`
- Includes EF6 agregados: `Technique`, `ControlPoints`
- **IMPORTANTE**: `IrradiationModality` y `ExactBeamEnergy` son null en todos los pacientes actuales porque el AriaRunner.exe local es una versión anterior. Hay que recompilar (mismo equipo Win10) y hacer "Actualizar ARIA" desde la UI para poblarlos.

### 4. Flujo de propagación ARIA (Application + Web)
- `BootstrapService.BuildAsync()`: propaga `IrradiationModality`+`ExactBeamEnergy` a pacientes → calcula `TreatmentLabel` → propaga a `AgendaItems` via GUID→HC map
- `POST /api/home/apply-aria`: misma propagación + recálculo
- `GET /api/agenda` (fechas futuras): enriquece slots scrapeados con `TreatmentLabel` del follow-up
- `AgendaSlotDto`: usa `src.TreatmentLabel` si ya viene propagado, sino recalcula desde texto de agenda

### 5. Configuración de capacidades por equipo (Web)
- `AppConfiguration`: defaults para 11 equipos (VMAT, IGRT, Electrones, TSET, etc.)
- `RtConfigurationHolder`: backfill de `MachineCapabilities` si el JSON guardado es anterior
- Tab Configuración: checkboxes colapsables por equipo (VMAT/Electrones/SBRT/RC/TBI/TSET/IGRT + 10X/15X/18X)

### 6. Frontend (app.js + styles.css)
- **Una sola función**: `renderTreatmentLabel(item)` reemplaza toda la lógica anterior de badges combinados
- **Eliminadas**: `treatmentBadge`, `beamBadge`, `modalityBadge`, `specialTechniqueBadge`
- **`ariaBadges(p)`**: simplificada — solo muestra `▸ máquina` (sin haz ni modalidad, ya están en el label)
- **Links en agenda**: `slot.sitraMedGuid` directo (ya no depende de lookup por nombre)
- **Filtro BQT/IORT**: `isExcludedTechnique()` — no aparecen en seguimiento ni física
- **CSS nuevo**: `.tt-VMAT` (verde), `.tt-TSET` (violeta)
