  MEVA RT - INSTRUCCIONES DE USO Y DESARROLLO

RESUMEN DE DIRECTORIOS Y PUERTOS
---------------------------------

  C:\Pablo\Meva.Rt\     → CODIGO FUENTE (git, edicion, desarrollo)
  C:\MevaRT\            → DESPLIEGUE (servicio Windows + datos)

  Puerto 5062           → URL unica: http://localhost:5062
                          Lo usa tanto el servicio como el modo dev.
                          Solo puede correr UNO a la vez.


MODO NORMAL (USO DIARIO)
------------------------
El servicio Windows "MevaRT" corre automaticamente al encender la PC.
Siempre disponible en http://localhost:5062

  - Codigo fuente: C:\Pablo\Meva.Rt\   (no hace falta tocarlo)
  - Ejecutable:    C:\MevaRT\Meva.Rt.Web.exe
  - Datos:         C:\MevaRT\data\
  - Logs AriaRunner: C:\MevaRT\data\aria_runner_*.log

Para actualizar datos: boton "Actualizar" en la web o correr refresh.bat


MODO DESARROLLO (cuando se modifica el codigo)
-----------------------------------------------
1. Detener el servicio (ocupa el puerto 5062):
     Stop-Service MevaRT

2. Editar el codigo en C:\Pablo\Meva.Rt\

3. Correr el servidor de desarrollo:
     cd C:\Pablo\Meva.Rt
     dotnet run --project Meva.Rt.Web

   Mismo puerto (5062), mismos datos (C:\MevaRT\data\) gracias a
   MEVA_DATA_DIR configurado en launchSettings.json.

4. Probar en http://localhost:5062

5. Al terminar, publicar los cambios y reiniciar el servicio:
     .\scripts\publish.ps1

   Esto compila en Release, copia a C:\MevaRT\ y reinicia el servicio.


ACTUALIZAR DATOS DE ARIA (boton web o refresh.bat)
---------------------------------------------------
El boton "Actualizar ARIA" en la web corre todo automaticamente:
  1. Lanza AriaRunner.exe (credenciales via variable de sistema ARIA_VARIAN_PASSWORD)
  2. Importa los resultados al mock
  3. Aplica los datos al snapshot del dashboard

Para actualizar todo (SitraMed + ARIA + agendas): boton "Actualizar todo"
o bien desde consola: scripts\refresh.bat

El script refresh.bat siempre apunta a http://localhost:5062, funciona
igual con el servicio corriendo o con el modo desarrollo.


VARIABLES DE ENTORNO DEL SISTEMA (configuradas, no tocar)
----------------------------------------------------------
  MEVA_ARIA_RUNNER_EXE  → C:\Pablo\Meva.Rt\Meva.Rt.AriaRunner\bin\Release\net9.0-windows\AriaRunner.exe
  ARIA_VARIAN_PASSWORD  → contrasena del usuario varian en ECL-FISICA2
  MEVA_HOME_REFRESH_MODE → (opcional) snapshot_first | snapshot_only | every_request


PUBLICAR CAMBIOS AL SERVICIO
-----------------------------
Desde consola de administrador en C:\Pablo\Meva.Rt:

  .\scripts\publish.ps1

Detiene el servicio, publica en Release a C:\MevaRT\ y lo reinicia.
Tarda ~30 segundos.


ARQUITECTURA DE CONEXION A ARIA
---------------------------------
AriaRunner.exe se ejecuta en esta PC y se conecta a ARIAMEVADB-SVR
usando impersonacion Windows (tecnica "runas /netonly") con el usuario
ECL-FISICA2\varian. No requiere que ese usuario exista localmente.


SOLUCION DE PROBLEMAS
---------------------
"Failed to fetch" o la web no responde
  → El servicio no esta corriendo. Verificar:
      Get-Service MevaRT
    Si esta detenido: Start-Service MevaRT
  → Si estas en modo dev: asegurarse de que dotnet run este corriendo.

"Falto el test de conexion ARIA"
  → Verificar variable ARIA_VARIAN_PASSWORD:
      [Environment]::GetEnvironmentVariable('ARIA_VARIAN_PASSWORD','Machine')
  → Verificar conectividad a ARIAMEVADB-SVR:
      Test-NetConnection -ComputerName ARIAMEVADB-SVR -Port 1433

"Error Win32: 1326" en el log de AriaRunner
  → Contrasena incorrecta para ECL-FISICA2\varian

"HTTP 000" en algun curl del refresh.bat
  → El servidor no esta corriendo en el puerto 5062

Puerto 5062 ya en uso al correr dotnet run
  → El servicio Windows sigue corriendo. Ejecutar: Stop-Service MevaRT
